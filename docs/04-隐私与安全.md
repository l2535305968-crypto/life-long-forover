# 隐私与安全

老人的人生故事属于高度隐私。本文列出威胁、对策、以及**代码里已经做到什么程度**，不含糊。

## 数据流向（唯一事实）

```
老人的话 ──> 手机浏览器（IndexedDB，本地）
              │  只把"最近几句对话"发给服务端，让 AI 生成下一句
              ▼
        家人的电脑（server.mjs）──> DeepSeek（生成下一句 / 传记）
              │  不落盘、不打印正文
              ▼
        只回一句"下一句问什么"，原路返回手机
```

## 威胁模型与对策

| 威胁 | 对策 | 状态 |
|------|------|------|
| Key 泄露给手机/前端 | Key 只在 `server.mjs`，前端只调 `/api/chat` | ✅ 已做 |
| 服务端把老人故事存下来 | 服务端不写任何日志正文，不落盘 | ✅ 已做 |
| 别人拿到导出文件 | 导出用 AES-256-GCM + PBKDF2(21 万次) + 口令，没口令打不开 | ✅ 已做（`crypto.js`，有测试） |
| 高频请求把 Key 用穿 | 每 IP 每分钟限流（`RATE_PER_MINUTE`） | ✅ 已做 |
| 目录穿越读服务器文件 | 静态服务 resolve 后强制限定在 `web/` | ✅ 已做 |
| 家人未授权查看 | 授权码 `grantCode` + 导出必须口令 | ⚠️ 授权码是轻量门，详见下 |
| 上游返回被原样透传 | 只回成功时的文本，失败只回人话 | ✅ 已做 |

## 授权码的诚实说明

`session.auth.grantCode` 是一个 8 位授权码，用来在"同一台设备上"挡住随手点开。它**不是**强加密，也不该被当成安全边界——真正的安全边界是**导出加密 + 口令**。跨设备分享的唯一通道是加密导出，授权码只做浅层防呆。

## 还没做 / 没验证的（不假装）

- **专业方言 ASR**：语音会经过第三方 ASR，那部分的数据处理协议要等选型后单独评估。当前录音只留在本地，不发给任何 ASR（转文字靠手机输入法，那是操作系统的事）。
- **服务端鉴权**：本机服务假设只在家人自己的网络里跑。若将来上公网托管，需要加访问令牌，这还没做，也不会假装做了。
- **DeepSeek 侧**：对话内容会发给 DeepSeek。用哪家、它的数据处理承诺，需要用户在配置里知情。README 已写明"联网只为让 AI 说得自然"。

## 底线一句话

能不留服务器的，都不留；必须上服务器的，只传"眼下这几句"，不留痕迹。
