## 一、当前线上真实拓扑（2026-08-28 核对）

```
用户手机浏览器
   │ https://shu.xunyiju.com
   ▼
Cloudflare Pages 项目 renshengzhishu
   ├── 前端静态资源   web/                → index.html / app.css / js/（书架、访谈、照片、时间线、传记）
   ├── /api/health    functions/api/health.js    → 反馈 hasKey / hasAsr / hasTts
   ├── /api/chat      functions/api/chat.js      → 真 DeepSeek 代理（AI 对话 / 传记）
   ├── /api/asr       functions/api/asr.js       → 方言识别反向代理 ↓（与 TTS 同一链路）
   └── /api/tts       functions/api/tts.js       → 暖声音反向代理 ↓
                         │ 两者都补 x-tts-token 请求头（识别/合成共用同一护门令牌）
                         ▼
                    https://tts.xunyiju.com      （cloudflared 固定隧道，QUIC 协议）
                         ▼
                    阿里云 ECS 8.137.13.183:8788  （node server/app.mjs，PM2 守护）
                         ├── /api/asr → 讯飞 IAT（方言识别，accent='mulacc' 免切换 202 种方言）
                         └── /api/tts → 讯飞 TTS（暖声音，WAV 回传）
```

**一句话：**
- **前端 + AI 对话 + 传记** → 全部走 Cloudflare Pages（零服务器，GitHub 自动部署）。
- **暖声音朗读** → Pages 代理 → 固定隧道 → 云服务器 → 讯飞 TTS（服务器就干这两件事）。
- **方言语音识别（讯飞 ASR）** → 现走与 TTS 同一条链：Pages `/api/asr` 反向代理 → 隧道 → 服务器 → 讯飞 IAT（`accent='mulacc'` 免切换识别 202 种方言，含川/粤/吴语）。前端读 `/api/health` 的 `hasAsr` 为真时优先选讯飞识别；隧道网络故障会自动降级浏览器内置（普通话）或打字。

## 二、版本发布流程（两种变更，两种流程）

### A. 只改前端 / Pages 后端（最常见：UI、对话、功能）

**只 push 到 GitHub `master`，Cloudflare Pages 自动构建上线。**

```bash
cd D:/life-long-forover

# 1. 看清改动（只应看到 web/、functions/、docs/ 等业务文件）
git status

# 2. 只暂存业务文件，别用 -A 误提密钥/构建产物
git add web/ functions/ docs/ .gitignore

# 3. 提交（中文，说明为什么）
git commit -m "改动说明"

# 4. 走代理推送（大陆直连 GitHub 443 常被断，本机代理在 127.0.0.1:7890）
#    用 -c 单次生效，不改 git config
git -c http.proxy=http://127.0.0.1:7890 push origin master
```

部署触发后，验证：
```bash
curl -s https://shu.xunyiju.com/api/health
# 看 hasKey:true。若 hasTts:true 说明服务器暖声音链路也活着。
```

> **标记版本（可选但推荐）：** 每次正式发布打一个 tag，方便回滚定位。
> ```bash
> git tag -a v0.N-说明 -m "版本说明"
> git -c http.proxy=http://127.0.0.1:7890 push origin v0.N-说明
> ```
> 已有 tag：`v0.2-warmvoice`、`v0.3-fixed-tunnel`、`v0.4-bookshelf-delete`。

### B. 改服务器（暖声音 TTS 相关：app.mjs、讯飞配置、隧道）

服务器改动**不会**因为 push 自动更新——必须手动同步到 ECS 并重启。

```bash
# 1. 本地改完 server/app.mjs 后上传（工具内含密码，绝不提交到 git）
python tools/ecs_ssh.py upload server/app.mjs /opt/renshengzhishu/server/app.mjs

# 2. 在服务器上重启 PM2 进程（必须带 --experimental-websocket，否则 WebSocket 未定义）
PM2HOME=/root/.pm2 /opt/node-v20.18.0-linux-x64/lib/node_modules/pm2/bin/pm2 \
  restart renshengzhishu --update-env --node-args='--experimental-websocket'

# 3. 若改了 env，需先写入再重启，且 .env 在服务器上手动改
#    （服务器 env 不跟随 git；用 PM2 的 env 或 app.mjs 内读取的 .env 文件）
```

> **服务器上确认运行状态：**
> ```bash
> PM2HOME=/root/.pm2 /opt/node-v20.18.0-linux-x64/lib/node_modules/pm2/bin/pm2 list
> # renshengzhishu 应 online；若 ↓ 次数多说明反复崩，看日志：
> PM2HOME=/root/.pm2 ... /pm2 logs renshengzhishu --lines 50
> ```

### C. 改 Pages 的环境变量（Key / secret）

```bash
# 改某个 secret（只存 CF，不进代码、不出明文）
echo "你的新值" | wrangler pages secret put RSZ_TTS_TOKEN --project-name renshengzhishu
# 改完必须重新部署一次才会注入 Functions
wrangler pages deploy web --project-name renshengzhishu --branch master
```

**「暖声音」两个关键 secret 要配对：**
- Pages 侧 `RSZ_TTS_TOKEN` 必须与服务器侧 `TTS_TOKEN` **同值**。
- 若只改一边，前端 `hasTts` 会 `true`（因为 Pages 侧有值），但实际请求会 401/403——**这是最容易踩的坑**。
- 上游地址 `RSZ_TTS_UPSTREAM` = `https://tts.xunyiju.com/api/tts`（带 `/api/tts` 前缀，本代理透传子路径）。

## 三、排查线上问题（按症状找根因）

| 症状 | 可能根因 | 先查什么 |
|------|----------|----------|
| 网页打不开 / 530 / 502 | 域名被别的入口抢了 / Pages 未部署 | `curl -s https://shu.xunyiju.com/api/health`，看返回话术 |
| `hasKey:false` | Pages 少了 `DEEPSEEK_API_KEY` | Pages 控制台 → Settings → Environment variables |
| **AI 没声音（暖声音全静音）** | ① Pages 缺 `RSZ_TTS_TOKEN` ② 服务器挂了 ③ 隧道断了 | 见下方"暖声音排查"专节 |
| 语音识别不工作 | ① Pages 缺/错 `RSZ_TTS_TOKEN`（hasAsr 由它决定）② 服务器挂了 ③ 隧道断了（降级浏览器普通话） | 看 `hasAsr` + 隧道 `401` 排查（同暖声音专节，`/api/asr` 与 `/api/tts` 同链） |
| 前后端读到的书不一致 | 用户换了设备/浏览器（IndexedDB 是本地的） | 确认同一台设备同一浏览器 |
| **push 后线上**没变化 / 资源仍是旧版 | Pages git 集成构建产出**空幽灵部署**（`wrangler pages deployment list` 可见建成，但部署 URL 所有资源 404）；自定义域可能仍服务上一个旧而可用的快照 | 见下方"部署未生效排查（专节）" |

### 暖声音排查（专节）

```
浏览器点"朗读"没声，按顺序查：
1. Pages 侧 token 在不在
   curl -s https://shu.xunyiju.com/api/health   → 看 hasTts 是否 true

2. 隧道通不通（无 token 应回 401，而非 502/超时）
   curl -s -o /dev/null -w "%{http_code}" -X POST https://tts.xunyiju.com/api/tts \
     -H "content-type: application/json" -d '{"text":"你好"}'
   # 401 = 隧道+服务+token 门都活着（正确）
   # 502 = 隧道断或服务没起
   # 000/超时 = 隧道连不上（ECS 出站到境外被断？）

3. 服务器服务在不在
   PM2HOME=/root/.pm2 ... /pm2 list   # renshengzhishu 应 online
   ss -tlnp | grep 8788               # node 应监听 8788

4. 隧道进程在不在
   ps aux | grep -i cloudflared | grep -v grep
   # 应看到 --protocol quic tunnel run --token-file ...（固定隧道）
```

**结论表：** `hasTts:true + 隧道 401 + PM2 online` → 链路健康；任一环断了逐环往上查。

### 部署未生效排查（专节）

**症状：** `git push origin master` 成功、`/api/health` 也正常，但改的页面/资源线上还是旧版（连改好几批都没上去）。

```
push 成功后线上没变化，按顺序查：
0. 先别怀疑代码——git 集成的 Pages 构建**偶发产出空幽灵部署**：
   wrangler pages deployment list --project-name renshengzhishu
   # 能看到一个 Source 等于你最新 commit 的 Production 部署，
   # 但点开它的部署 URL（https://<id>.renshengzhishu.pages.dev）所有资源都 404
   # 而 shu.xunyiju.com 还在服务上一个"旧但可用"的快照 → 这就是空幽灵部署。

1. 确认远端确实有你的 commit（排除 push 没成）
   git -c http.proxy=http://127.0.0.1:7890 ls-remote origin master
   # 应等于本地 git rev-parse HEAD

2. 绕过 git 构建，手动直传修复（最稳，见 §二.C）
   PYTHONIOENCODING=utf-8 npx --no-install wrangler pages deploy web \
     --project-name renshengzhishu --branch master
   # 会生成一个新部署 URL（形如 https://f6b2cbd1.renshengzhishu.pages.dev）

3. 用缓存穿透参数验证新部署真的带上了你的改动：
   curl -s "https://<新部署id>.renshengzhishu.pages.dev/<资源>?cb=$RANDOM" | grep <特征串>
   # 例：curl -s "https://<id>.pages.dev/app.css?cb=123" | grep -c "translateY(-100vh)"

4. 确认自定义域切到新部署：
   curl -s "https://shu.xunyiju.com/app.css?cb=$RANDOM" | grep -c <特征串>

结论：`ls-remote == HEAD` + `部署 URL 资源齐全` + `自定义域命中特征串` → 已生效。
生成的新部署 URL 是"活着"的那个；若发现旧的空幽灵部署在列表里，
可在 Cloudflare 控制台删除（wrangler 删除需交互确认，非交互下会拒绝）。
```

**为什么 git 集成会空部署：** Pages 从 git 构建时，若 build command/输出目录配置下产出为空、或构建被静默中断，仍会登记一个 Production 状态但**没有任何文件**的部署。此时自定义域未必回滚，会继续服务上一个可用快照，造成"push 了但没上线"的错觉。**对策：改用 `wrangler pages deploy web` 手动直传**（它就是把你本机 `web/` 直接上传，绕开 git 构建），这也是文档 §二 里 A/C 流程最可靠的兜底。

## 四、风险清单

### 🔴 高危（必须守住）
| 风险 | 说明 | 对策 |
|------|------|------|
| **密钥/密码泄露** | 服务器 SSH 密码写死在本机 `tools/ecs_ssh.py`（明文）、Cloudflare token 在本地文件、AccessKey.csv 在硬盘 | **绝不允许提交这些文件到 git**（已在 .gitignore 与提交时反复确认）；只在本机用；定期轮换密码 |
| 端口被扫/刷 | 服务器 8788 曾为调试开过公网；临时 quick 隧道把 8788 暴露到随机域名 | **公网安全组只留 22（管理）+ cloudflared 所需；不要放行 8788 到 0.0.0.0**；8788 只让本机 + 隧道访问 |
| **token 单点失效** | Pages `RSZ_TTS_TOKEN` 与服务器 `TTS_TOKEN` 不同值 → 语音全挂但 `hasTts` 仍 true，迷惑性极强 | 改任何一边 token，必须同步另一边；改完用上面"3. 隧道 401"验证 |

### 🟡 中危（容易复发）
| 风险 | 说明 | 对策 |
|------|------|------|
| **跨境出站阻断** | 阿里云这台 ECS 出站到境外（Cloudflare 边缘）曾全断 → 隧道连不上。cloudflared 走同一 Cloudflare 网络通常能绕过，但**不是保证** | 若`tts` 隧道反复断，先测服务器 `curl https://1.1.1.1`（境外）vs `curl https://www.baidu.com`（国内），判断是否又是跨境断；是则重启隧道或寻求其他出口 |
| 临时残留进程 | 调试留下的 quick 隧道（`cloudflared tunnel --url`）会占进程、把端口暴露到随机域名 | 定期 `ps aux | grep cloudflared`，只保留 `--token-file` 那条固定隧道；多余的杀掉 |
| **文档漂移** | `05b` 曾记"云服务器已弃用"，但当前已复用于暖声音 → 误导后来人 | 已在本文件顶部与 `05b` 加更正指引；以后改链路**同步更新文档** |
| 环境变量改完没重部署 | Pages 的 secret 改了但没 `pages deploy`，Functions 读不到旧值 | 固定流程：改 secret → 必 `wrangler pages deploy` 一次 |
| **git 集成构建空部署** | push 成功但 Pages git 构建偶发产出**空幽灵部署**（所有资源 404），自定义域仍服务旧快照 → "push 了却没上线" | push 后务必用"部署未生效排查"验证；一旦发现空部署，用 `wrangler pages deploy web --branch master` 手动直传兜底 |

### 🟢 低危（预期行为 / 兜底）
| 风险 | 说明 |
|------|------|
| 隧道/服务器断时方言识别降级 | `/api/asr` 与 `/api/tts` 共链，隧道或服务器断则方言不可用；前端自动降级浏览器内置（普通话）或打字——不是 bug，是兜底 |
| 书只在本机 | IndexedDB 是浏览器本地存储，换设备/清缓存就没了；导出必须设口令 |
| 免费额度 | 讯飞听写 500 次/天、DeepSeek 按 token 计费——家庭自用够，量大了去控制台提额 |
