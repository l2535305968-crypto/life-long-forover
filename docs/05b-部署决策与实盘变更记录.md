## 二、为什么从"云服务器（D 方案）"转向"纯 Pages（B 方案）"

> 背景：用户最初想长期给多个家庭用，需要"完整语音（含讯飞方言识别）"，所以一路搭了云服务器 D 方案（阿里云 `8.137.13.183`，node 服务 8788，PM2 守护，Cloudflare Tunnel 套 https）。

**转折点（本次实盘踩坑）：**

1. 手机端刷新失败 → 排查发现 `shu.xunyiju.com` 其实一直被 **Cloudflare Pages 的旧部署**占着（用户手动绑定过），而不是云服务器隧道。
2. 解绑 Pages 域名后，域名 HTTP **530**（隧道断连）。
3. 尝试把 cloudflared 隧道切到 **QUIC 协议**重连 → 失败。
4. **根因定位（关键）**：云服务器 `8.137.13.183` 出站到**境外**（Cloudflare 边缘 `198.41.192.x`）**完全不通**，但**国内正常**：
   - `ping 1.1.1.1` → 丢包 100%
   - `curl https://1.1.1.1`（443 TCP）→ 超时，`000`
   - `curl https://www.baidu.com` → `200`（0.14s）✅
   - 本机回环 `127.0.0.1:8788/api/health` → `200` ✅（node 服务本身健康）

   **这是"服务器能到国内、到不了境外"的典型跨境出站阻断**。cloudflared 隧道恰恰需要连云境外的 Cloudflare 边缘，所以换 QUIC/TCP 协议都无解，问题在网络层。

**决策：** 既然云服务器走不通（出站到境外被断），且用户已确认 Pages 连了 GitHub、域名也绑了，就直接用 **方案一：纯 Cloudflare Pages**。它零成本、零维护、自带 https、AI 对话完整；唯一牺牲是**讯飞方言识别**（Pages Functions 无法主动发起对讯飞的 WebSocket），语音自动降级为浏览器内置识别或打字。

## 六、踩坑与经验（以后改这项目必看）

1. **域名被谁托管，直接决定线上跑的是什么代码。** `secureContextNote` 是判别标志：含 "Cloudflare Pages" = Pages；若之前是隧道/node 服务会有另一句话术，或直接 530/502。
2. **"出站网络不通"要分方向测：** ping 国内 ≠ 能到境外。务必分别测 `ping 1.1.1.1`（境外）和 `ping www.baidu.com`（国内）。跨境断连时，换 QUIC/TCP 协议无用。
3. **Pages 自定义域只能用控制台绑定**，`wrangler pages` v4 没有 `domain` 子命令。
4. **（2026-08-28 更新）方言识别已上线**：Pages `/api/asr` 改为反向代理，与 `/api/tts` 同链走 cloudflared 隧道 → 服务器 8788 → 讯飞 IAT（`accent='mulacc'` 免切换 202 种方言）。`hasAsr` 由 Pages 的 `RSZ_TTS_TOKEN` 决定（不再读讯飞三件套，那三件套只存服务器 `.env`）。隧道/服务器断时会自动降级浏览器普通话或打字。**别再用旧认知"Pages 必不支持讯飞"——现在能了。**
5. Key 只存 Cloudflare secret / 服务器 `.env`，**绝不写进前端代码或提交到 git**。

## 八、空部署事故根因与修复（2026-08-28）

**症状**：线上静态资源全 404（`/js/app.js` 也 404），瞬间打挂；多人/多端打开"人生之书"即空白。

**根因**：`wrangler.toml` 的 `pages_build_output_dir` 被写成 `""`（空字符串）。Cloudflare Pages 的 **git 集成**构建靠这个字段判断"把哪个目录发到线上"。值为空 → Pages 不知道该发什么 → 产出**空部署**（0 字节），所有静态资源 404。这不怪 git 上传失败——git 上传是好的，是 Pages 拿到了 `""` 不知道该发布哪个目录。

**修复**（点 ①，动一个字符）：
```toml
# wrangler.toml
name = "renshengzhishu"
pages_build_output_dir = "web"   # 原来："" ← 改成这个，git 集成才知道发 web/ 目录
compatibility_date = "2026-08-27"
```

**验证**：`bash tools/check_deploy.sh`（新增的健康哨兵）→ `/js/app.js` 需 HTTP 200 且 >20KB，`/api/health` 需返回 `ok:true`。当前线上状态：两者都通过。

**推荐流程（治本）**：以后改动**优先走 git 推送**（`git add` + `commit` + `push`），让 Pages 的 git 集成从 `web/` 构建；它不会再产出空部署，因为 `pages_build_output_dir="web"` 已生效。若某次要立即上线某个本地改动、懒得走 git，再用 `wrangler pages deploy web --project-name renshengzhishu` 手动覆盖（两张路径现在都安全）。

**幽灵部署清理法**：
```bash
# 列出所有部署（含 UUID、状态、时间），找出返回非 200 的空部署
wrangler pages deployment list --project-name renshengzhishu
# 逐个删除（必须带 -f，否则交互式默认"no"删不掉）
wrangler pages deployment delete <uuid> --project-name renshengzhishu -f
```

## 九、访谈"认人"改进（option A，2026-08-28 已上线验证）

**改了什么**（都在 `web/js/`，已部署，线上 live）：
- `prompt.js` 新增 **rule 0d**：先认对方是不是老人。若对方明说"我还很年轻 / 我不是你爷爷 / 我是帮家里老人记的"，AI 立刻放下"您、大爷、炕头、那会儿您"那套，顺着对方身份聊。**判断标准是对方自己的话，不是预设。** 并补一句：落到来往称呼也一样，**别自作主张给人定"闺女/孩子"**，照开场的规矩自然问一声怎么称呼。
- `prompt.js` 加固 **rule 4**：对方明确不想聊某方向（"为什么一定要说我小时候"），就顺着换到他当下想聊的地方，别绕回被拒绝的方向。
- `app.js` 新增 `OPENING_VERSION = 2`：旧书缓存的"我是来记您一辈子的"开场白，会在下次打开时重新生成为"还不知道您怎么称呼呢……"。**这是「改版后旧书也生效」的关键——缓存字段要加版本号才刷新得动。**

**实机验证结果**（Playwright + 真实 DeepSeek）：
- ✅ 开场白："还不知道您怎么称呼呢，您说是喊大爷、大叔、还是老爷子？"（不再劈头砸问题、不再自报"我来记您一辈子"）。
- ✅ 对方说"我还很年轻，我是帮我爸来记的" → AI 接住："那敢情好，替爹记事儿呢。"（不再硬撑"陪老人"口吻）。
- ⚠️ 发现并修复一个边角：修复前 AI 会单方面给人定"那我喊你闺女吧"（越界、太亲）。已按 rule 0d 补丁禁止，用"自然问一句怎么称呼"替代。

**注意**：rule 0d 是"刹车"，不是"换节目"。只要对方没说自己不是老人，AI 仍照常陪长辈唠；一旦他明说，才换口吻。**这一步只做到"认得是谁"，不改变整本书的定位。**
